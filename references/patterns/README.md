# Patterns

Named methodologies an adopter may choose to apply within their domains or rituals. The harness has no opinion on which (if any) an adopter uses.

Each pattern is a single markdown page with:
- A one-paragraph summary
- A "when to use" note
- A link to the canonical source

## Shipped pattern stubs

- `wardley-mapping.md` — situational-awareness mapping (Simon Wardley)
- `team-topologies.md` — four team types + three interaction modes (Skelton & Pais)
- `flow-engineering.md` — five-map sequence for value-stream alignment (Steve Pereira)
- `okrs.md` — outcome-oriented planning (Doerr, Wodtke)
- `opportunity-solution-trees.md` — continuous discovery (Teresa Torres)

## Adding a pattern

1. Single markdown file in this folder.
2. ≤120 words summary, ≤120 words "when to use", canonical source link.
3. Do not paraphrase the pattern's actual mechanics — link to the source.
4. Do not present a pattern as "the harness's choice" — it is one option.

## What this folder is NOT

- Not a methodology library. Adopters bring methodologies; the harness collects them.
- Not load-bearing. The harness works without any pattern from this folder.
